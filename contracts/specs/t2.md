# T2：保障研判与人工决定

在T1成果上增量开发。

## F01–F04：一次分析

POST /api/inventories/{id}/ai-replenishment，仅ADMIN及授权DISPATCHER。读取当前库存版本、物资阈值及T1本日统计，按itemNos/关键词从预置knowledge-baseline.json取当前可见ACTIVE资料。无需单独检索接口、历史单据召回、历史quote或topK/向量算法。

### 统计范围

本次统计固定为所选库存的 `warehouseId + itemId`，等价于调用 T1 统计时同时传入这两个筛选条件。统计该仓该物资的全部领用人，不仅统计当前操作者；不扩展到同部门、下级部门或其他授权仓库。沿用北京时间本日、退回不抵扣、套料只计明细和排除未来记录的规则。

`context.issueStats.scope` 用非空字符串明确实际仓库和物资，例如 `仓库4101/物资5101`；格式不限，ID 来自当前库存，不能硬编码。`quantity=0` 表示查询成功且无本日领用，不能把查询失败伪装成 0。`asOf` 为本次统计的服务端业务模拟时间。

### 知识可见性与适用性

| 条件 | 处理规则 |
| --- | --- |
| `deptId=null` | 公共可见，仍须满足有效性和适用性条件 |
| `deptId` 为部门 ID | 按当前用户部门权限范围过滤，越权资料不得送入模型 |
| `status=INACTIVE` | 不作为本次支持依据 |
| `itemNos` 非空 | 仅可用于列表内的物资；关键词提及其他物资不能越过此限制 |
| `itemNos=[]` | 通用资料，可检索并引用正文实际覆盖的通用规则；不视为所有物资的维护资料 |

只命中通用资料、未取得当前物资适用维护资料时，仍应列出该缺口并要求人工复核。公共可见且 `itemNos` 包含当前物资的有效维护资料可以作为该物资依据。正文中的旧盘点数量不能作为实时库存，资料明确冲突仍须复核。上述规则同样适用于 T3 复用本次知识。

### 模型、引用与分析记录

真实HTTP模型收到本次知识和业务数据，生成suggestion={warehouseId,itemId,suggestedQuantity,reason,confidence,needHuman,knowledgeReferences}；旧references可省略或为空[]，不接收历史引用。quantity为0～500整数。知识引用{docId,title,version,quote}来自本次送入模型的实际文档，quote连续原文，建议实体与当前库存一致。禁止固定答案。

响应使用advice-response.schema.json：callId/inventoryId/inventoryVersion/suggestion/degraded/requiresHumanReview/reviewItems/decision/context。context.inventory保存实际快照；issueStats={period:TODAY,quantity,scope,asOf}，knowledge保存本次已授权文档/片段；无需history字段。复用AICallLog保存PENDING记录，无库存变更。

引用查看可在当前建议卡片直接展开context中的本次来源原文；无独立GET知识列表/详情必考要求。页面重新读取分析时重新校验当前范围，不下发失权资料。知识是考试期间固定文件，不验收热更新、点击旧版本、重建索引的生命周期。

理由说明当前余额、补货点/目标库存和本日领用量如何支持建议。维护资料不能证明实时数字；不要求唯一最优数量，不做采购预测准确率测试。无本日领用的真实统计0是有效数据，不因无历史逐条案例强制降级。

## F05–F07：复核及三种决定

仅无适用知识、显式冲突或模型降级时必须列reviewItems并由服务端要求reviewed=true；可继续支持模型needHuman及低置信度，但不验收复杂复核优先级矩阵。冲突用两篇明确矛盾的资料测试，不考隐含语义推理。复核不绕过权限/版本。

POST /api/inventories/{id}/ai-replenishment/{callId}/adopt为{reviewed}；adopt-edited为{suggestedQuantity,reason,reviewed}；reject为{}。服务端沿用原实体/引用，不接收客户端伪造的needHuman、引用或身份。采纳重查权限及库存版本，变化返回VERSION_CONFLICT，用户重新分析。拒绝只检查当前权限及PENDING，不要求复核或旧版本仍一致。

待办补充计划直接保存为AICallLog.final_suggestion和decision=ADOPTED/ADOPTED_EDITED。context.decisionMeta可保存reviewed、actorId、at；原suggestion/context保留，不改写原依据。拒绝REJECTED、无补充计划。quantity=0可以采纳为“无需补充”的决定，不创建正数订单，不要求NO_REPLENISHMENT_NEEDED分支。

同一条记录以PENDING条件更新一次，重复决定AI_DECISION_CONFLICT。决定字段一次事务保存，失败仍PENDING；不要求独立t_replenishment_draft、草稿编号、草稿编辑/审批或跨表审计事务。旧库中已存在的草稿数据由0006保留，不再提供相应模型或读写业务；新库不保留空草稿表。

GET /api/inventories/{id}/ai-replenishment/{callId}预置为鉴权后的501入口，考生实现返回分析及finalSuggestion/reviewed/decisionById/decisionAt，当前范围鉴权；结果在同一建议卡片展示，无新列表页要求。刷新后仍可按已知callId查看决定。

## F08：失败边界

模型超时、非法JSON/实体/引用时可立即降级，不要求自动重试。真实库存可取得时备用数量=max(0,min(500,targetStock-onHand))，confidence=0、needHuman/requiresHumanReview/degraded=true，引用为空并明确原因。仅此备用规则可以不用模型生成，但不能假装模型成功。当前库存不可取则返回查询错误，不保存编造建议。

HTTP客户端/超时和安全输出沿用现有；不展示密钥、不执行脚本/SQL。本日统计失败可明确失败后由用户重试，不要求多来源部分成功状态机。公开验收为一个正常分析、缺知识/冲突代表分支、三种决定及一个上游异常；不穷举全部服务组合。
