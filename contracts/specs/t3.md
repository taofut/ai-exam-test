# T3：备件调拨对话助手

在T1/T2上增量开发。

## F01/F02：查询与研判复用

统一POST /api/agent/run，{message,sessionId?,confirmToken?}。规则或模型路由均可，不强制tool_calls。查询指定仓库/物资当前库存，按需调用或读取T2建议和决定。维护回答仍使用真实模型，可复用T2检索/上下文；不要求另一套检索或独立历史检索。T2已采纳计划不等于到货/调拨授权，用户须明确调拨数量。

## F03：最低SSE闭环

页面发送Accept:text/event-stream，服务端发送meta→真实progress→result或error。沿用agent-stream-event.schema.json，id为turnId:序号，可只在单次响应内递增，无持久事件/游标存储。meta包含sessionId/turnId；progress={phase,message}在对应耗时步骤前发送；result为完整agent-response；error={code,message,outcome:FAILED|UNKNOWN}。每帧event/id/data加空行，UTF-8；成功或错误终态后结束。

最低验收：受控模型有延迟时，最终结果前页面已展示真实progress；一次网络拆块/粘包后仍能正确还原事件；一个result或error能结束等待。允许使用成熟SSE解析库，不要求手写解析器、模型token流、delta、心跳、CRLF兼容矩阵、Last-Event-ID、自动重连或回放。预置Schema仅提供上述四类事件，不再提供delta扩展。JSON兼容可保留，不强制两套前端流程。

sessionId服务端生成并绑定本人，内存保存当前物资/两库/数量/预览。不同用户不能继续同一会话；切换身份沿用已有AbortController及请求隔离，中止旧流。不考浏览器刷新、服务重启后恢复未完成会话。

## F04/F05/F06：澄清、预览与确认

缺少一个参数时保留其余并补问；同名对象展示可见编号/部门；明确修改作废旧预览。禁止擅自选库、数量或多意图自动执行。

两库不同、均有同itemId库存行、源足量及本人有双库权限时，只读预览返回CONFIRM_REQUIRED、preview及顶层confirmToken/confirmExpiresAt。展示真实前后余额；令牌绑定当前用户/会话/全部参数及双版本。TTL可配置或固定合理值，不指定实现。

本人明确确认才办理；T2采纳、资料和模型输出不能确认。当前权限、双版本和令牌满足后执行。版本变化返回VERSION_CONFLICT并使旧预览无效，页面提示重新预览；无需在失败响应中自动生成新预览或差异比较面板。

## F07/F08：原子执行和结果

一次事务完成源减目标增、双方版本+1、真实调拨单、双方流水及审计；成功记录保存绑定本次确认的唯一标识（可令牌摘要），避免重复/并发确认。条件不满足或提交前故障全回滚，数量守恒。

原令牌显式核对时，先检查当前身份、原会话绑定及双库权限，再查找该令牌对应的成功记录；不能先因令牌过期或旧版本变化而拒绝返回已提交结果。

| 原操作状态 | 核对行为 |
| --- | --- |
| 已成功，原会话有效、本人且当前仍有双库权限 | 返回原 EXECUTED 结果及执行时快照；即使令牌已过期也可核对，不校验旧库存版本，不再次写入 |
| 未成功，令牌仍有效且原确认的全部条件满足 | 可完成原次确认一次，返回真实提交结果；继续执行权限、版本和唯一执行约束 |
| 未成功，令牌已过期或已作废 | 返回 CONFIRM_INVALID，不办理；用户重新请求预览并确认 |
| 未成功，令牌未过期但双库存版本变化 | 返回 VERSION_CONFLICT，旧预览失效，用户重新预览并确认 |
| 非本人、当前权限不足或原会话失效 | 拒绝核对或执行；越权不泄露原结果，会话失效后不恢复旧确认 |

`confirmExpiresAt` 只限制尚未成功的原确认能否执行，不抹除成功记录。界面必须告知用户“核对/完成原次确认”，因为尚未成功时核对可能产生一次原业务写入；不能创建新确认或自动重试。无需独立按单号搜索接口/历史页，单号及结果在当前会话显示；成功业务记录持久化，重启会话失效后不得自动执行旧确认。

result只在真实提交后发出。error或无终态EOF停止等待，结果不明标UNKNOWN，断流不等于事务回滚。页面保留原会话/令牌供用户显式核对，不自动重连发送写请求。progress不触发业务写入。只验证一个成功响应丢失场景，不要求持久任务调度、取消竞争或复杂恢复。

预置preview/confirm路由仅可选复用；已移除独立手动调拨表单，TransferPreview卡片可用于对话结果；t_stock_transfer可由考生追加迁移。已有模型/查询/事务辅助可共用。不恢复独立计划草稿、采购、run/step/event、检查点或步骤重试。
