# T1：单物资与维修套料领退

每级8项，套料为F01，库存查询并入F06。保持单物资业务，新增工作集中在2～5行原子领退。父单、明细、外键和历史兼容均预置。

角色操作资格按 [公共契约的权限矩阵](../common.md)：ADMIN 可代退全部仓库内他人的单据，DISPATCHER 可代退本部门及下级仓库内他人的单据；ENGINEER 仅退本人且原仓当前有权访问的单据，REPORTER 不可退回。规则同时适用于单物资单和套料父单；套料子明细不能单退。代退保留原领用人，流水与审计记录实际退回操作者。

## 查询与预置结构

复用/api/inventories、/{id}、/api/warehouses、/api/items和/api/material-issues、/{id}。明细含issueOrderId，普通单及预置历史为null。套料子明细canReturn=false，页面引向父单整退。同一已有记录页分组/展开完整清单即可，不要求独立套料导航、搜索分页页或动态导出。

0004提供MaterialIssue；0005提供MaterialIssueOrder(id,order_no,warehouse_id,issued_by_id,reason_text,issued_at,returned_at,version)及MaterialIssue.issue_order_id可空外键。状态由returned_at派生ISSUED/RETURNED，不要求额外status列。已有同名表和关联列不覆盖，历史导入不改库存，旧单关联为空。

GET /api/material-issues/stats只提供period=TODAY、groupBy=ITEM（均可省略），保留warehouseId/itemId筛选，返回{totalQuantity,groups}。groups包含itemId/itemNo/name/unit/quantity；未指定itemId时totalQuantity=null，指定时为该物资合计。按物资与单位展示；套料按明细计一次、父单不计，退回不抵扣；北京时间[零点,次日零点)，排除未来。保留两处预置权限/日界修复任务。

## 单物资接口

POST /api/inventories/{id}/issue：{quantity,version,reasonText?,requestId?}，requestId仅兼容，不要求使用。正整数quantity、非负version、理由最多500字符。授权、版本、余额满足后一次事务扣库、库存版本+1、生成MaterialIssue(初始version=0)及流水审计；返回{issue,inventory}，可选replayed:false仅兼容旧客户端。

POST /api/material-issues/{id}/return：{issueVersion,inventoryVersion,requestId?}。沿用原数量和原仓，单据/库存版本+1，returnedAt及RETURN流水/审计同时保存。新数量/物资/仓库不接受。对有权访问的套料子明细返回KIT_RETURN_REQUIRED，不能绕过父单部分退库。

## 套料接口

| 接口 | 请求 | 成功响应 |
| --- | --- | --- |
| POST /api/material-issue-orders | {warehouseId,reasonText?,lines:[{inventoryId,quantity,version}]} | {order,lines,inventories} |
| GET /api/material-issue-orders | mine/warehouseId/status可选 | {items:[order,...]} |
| GET /api/material-issue-orders/{id} | 父单ID | {order,lines} |
| POST /api/material-issue-orders/{id}/return | {orderVersion,lines:[{inventoryId,inventoryVersion}]} | {order,lines,inventories} |

order返回实际id、orderNo、warehouseId、issuedById、issuedAt、returnedAt、version、派生status和permissions.canReturn；lines为真实原清单，包含各明细id/issueNo/issueOrderId/quantity、物资信息及当前inventoryVersion。inventories为成功后实际库存。可选replayed=false兼容，不要求requestId或返回旧成功响应。

同仓2～5种不同itemId，每种一行，库存已存在、数量正整数；不能重复物资、混仓或自动合并/改量。全部行授权通过后校验版本和余额；失败只需首个明确原因，不要求details或固定校验优先级。返回不得泄露越权行名称/余额。行数/重复/跨仓/退回集合错误KIT_LINES_INVALID，数量错QUANTITY_INVALID，版本冲突VERSION_CONFLICT，余额不足STOCK_INSUFFICIENT。

套料领用：一个事务完成所有库存条件更新及各版本+1、父单和所有明细、各物资流水及审计。任一失败整体回滚；不能循环调用已独立提交的单物资接口。父子初始version=0、returnedAt=null，单号服务端生成。

套料退回：行集合与原单完全一致（集合校验不要求输入排序），不收新数量或仓库；原父单状态/版本和每个库存版本匹配后，所有原数量加回，父子单version+1、同一returnedAt及各流水/审计一次保存。父单已退ISSUE_ALREADY_RETURNED；任一行失败全部回滚。

## 防重与限时边界

保留版本条件更新及原单状态保护：两个重叠请求用相同旧库存版本至多一单成功，另一单所有变化回滚；同单并发退回至多增库一次。重复旧请求可返回版本/状态冲突，不是必须重放成功；不考通用幂等键、参数摘要、换序重放、跨接口请求空间或t_request_result。

故障验收只注入一个“某行更新后、提交前”异常，验证整单回滚；不穷举每个写点。未收到结果只提示查询记录，不自动重发，不做跨刷新恢复/精准请求核对系统。现有事务/CAS辅助可复用。

页面从现有库存页添加套料清单，并在原记录页展示/整退，可用同页弹层，不单独建设父单管理平台。T1结构已预置，业务答案仍由考生实现。
